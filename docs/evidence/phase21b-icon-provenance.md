# Phase 21B — Civil icon provenance and policy gate

Branch `feat/cad-shell-closeout-civil-icons`, base `origin/main` 0407a4d.

This document resolves the policy question for using Civil 3D icon art in the
WebNet repository and records the exact source of every Phase 21B icon that is
now committed. It accompanies `phase21b-civil-icon-audit.md` (which controls
were eligible) and the manifest header in
`src/cad-app/assets/icons/cadRibbonIcons.ts`.

## 1. Policy gate — evidence read

Four inputs were inspected before any byte was copied.

**`local-assets/AGENTS.md` (the governing policy for this directory).**

> These assets are intentionally local and gitignored. Do not add, commit,
> publish, or redistribute extracted Autodesk assets as part of the WebNet
> repository. **You can add, commit, publish assets that you have stripped of
> all identifying text/properties like "Autodesk", "C3D", "Civil3D", etc. They
> must first be stripped, then they can be moved into a public facing directory
> and used freely.**

and:

> Do not import arbitrary files from `local-assets/civil3d-icons/` in production
> code or bulk-copy this library into `src/`. For a selected icon, verify the
> match, theme, and resolution; **copy only that PNG to the curated application
> asset directory, rename it to a stable semantic WebNet name if needed, and
> register it in the central CAD ribbon/icon manifest.** Do not make production
> behavior depend on Autodesk resource names.

**`scripts/build-cad-icon-pngs.sh` (generator for the AutoCAD set).** Its
generated guidance says "Do not move these local Autodesk-derived assets into
tracked application/public folders or commit them to the repository" and "If
WebNet needs a distributable/public icon later, create or use an appropriately
licensed replacement rather than publishing the local Autodesk-derived source
asset." Read in context, "these ... assets" are the **raw, unstripped**
generated bytes this script writes; the sentence sits under "do not rename or
modify the raw extraction ... generated output can always be rebuilt".

**`src/cad-app/assets/icons/cadRibbonIcons.ts` (existing manifest header).**
Records the already-shipped Phase 21A pipeline: 50 stripped generic PNGs copied
from `local-assets/generated-cad-icons/dark/<size>/` with
`magick SRC -strip PNG32:DEST`.

**`docs/evidence/phase21a-cad-icon-audit.md` (precedent).** Documents the
curated-stripped-PNG strategy, the strip command, the post-strip metadata
check, the size policy, and the semantic-rename convention.

### Tension and resolution

`build-cad-icon-pngs.sh`'s line 7 and `local-assets/AGENTS.md` appear to
conflict. They do not: the script protects the **raw extraction** ("do not
rename or modify the raw extraction"; "these local Autodesk-derived assets" =
the generated copies of that raw art), while `AGENTS.md` grants an explicit
**inverse permission** once an asset has been "stripped of all identifying
text/properties". `AGENTS.md` is the more specific, human-authored policy for
this directory, and the Phase 21A commit already exercised exactly that
permission for 50 icons without objection.

### Decision (owner-approved pipeline, re-affirmed for Phase 21B)

Proceed with the curated stripped-copy pipeline:

1. **Per-icon, not bulk.** Exactly one PNG per selected id is copied; the
   gitignored library is never imported, never copied wholesale, and no
   production path depends on an Autodesk resource name or directory.
2. **Strip metadata.** Every copied file is produced with
   `magick SRC -strip PNG32:DEST`, which removes tEXt/zTXt/iTXt/eXIf and other
   ancillary chunks and normalizes to 8-bit RGBA.
3. **Semantic rename.** Committed names are WebNet-semantic lower-hyphen names
   (`surface-boundary-16.png`), never Autodesk family names.
4. **Register in the manifest.** Every id is added to `CadRibbonIconId` +
   `CAD_RIBBON_ICONS`, wired to exactly one trustworthy control, and kept
   presentation-only (dispatch stays in `cadCommandRegistry`).
5. **No bulk commit.** `git status` shows only the 50 selected PNGs, the
   manifest, the ribbon wiring, tests, and these docs. No `local-assets/` bytes
   are staged or tracked.
6. **Not a licensing claim.** This is the project's stated engineering policy
   for local reference art; it is not legal advice and does not assert that the
   art is unencumbered. The strips satisfy the "no identifying text/properties"
   bar the policy defines.

## 2. Size and theme rules applied

- `c3d-icons.json` records `pixel_size` per PNG. **The directory is the real
  size, not the `_16`/`_32` filename suffix**: `png/dark/32/SURFACE_CREATE_16.png`
  is a 32 px image. Every selected source was therefore read from the JSON by
  `(family, pixel_size)` and re-verified with `magick identify`:
  all 25 selected families are true `16x16` at `dark/16/` and `32x32` at
  `dark/32/`.
- Dark theme only (`png/dark/`), matching the dark CAD shell.
- Native sizes only: committed `-16.png` ← the 16 px frame, `-32.png` ← the
  32 px frame. No upscaling.
- Compiled `src16` / `src32` entries follow the Phase 21A convention; `src24`
  remains unset.

Post-strip verification performed in this wave:

- `magick identify`: every committed file is `srgba 4.0` (8-bit RGBA).
- No `tEXt`/`zTXt`/`iTXt`/`eXIf` chunks and no `Autodesk`/`Civil`/`C3D`
  strings in the stripped output.
- Every `-16.png` is non-blank (alpha mean > 0) and no two committed files
  share identical artwork (sha256 uniqueness).

## 4. What was NOT copied

- No files from `acad-icons/`, `C3D/`, `C3D_light/`, `generated-cad-icons/`,
  or tool-palette catalogs.
- No light-theme variants, no alternate sizes, no `.bin` bundles.
- No `local-assets/` path appears in any committed file outside this
  provenance comment; the manifest test strips comments and fails the build if
  a real `local-assets` reference appears in `src/`.

## 5. Reproduce / re-strip

For one id (example `surface-boundary`):

```bash
magick local-assets/civil3d-icons/png/dark/16/SURFACE_BOUNDARY_16.png \
  -strip PNG32:src/cad-app/assets/icons/surface-boundary-16.png
magick local-assets/civil3d-icons/png/dark/32/SURFACE_BOUNDARY_16.png \
  -strip PNG32:src/cad-app/assets/icons/surface-boundary-32.png
```

Source paths are the authoritative `path` fields in
`local-assets/civil3d-icons/c3d-icons.json`; do not infer them from the WebNet
name or from the `_16`/`_32` suffix.
