## 1. Scope pin

20B grades ONE physical Feature Line course on ONE side per `CadGrading` definition. UI "Both Sides" atomically creates two independent single-side definitions. No multi-course corner grading (no miter/bisector/fan/clip assumptions), no grading groups, no design-surface auto-compose, no raster/DEM, no search-step solver, no corridor engine, no vertical curves, no retaining walls. Corners and groups belong to 20C if evidence supports continuing.

## 2. Source-course identity and persisted direction

Courses have stable VERTEX IDs, not course IDs. Persist `sourceCourse: { vertexAId, vertexBId }` — never a raw course index. Resolution: find a current course whose endpoints match the pair in either orientation, with an adjacency check (insert between A/B breaks adjacency → `BROKEN_REFERENCE`; endpoint delete → `BROKEN_REFERENCE`; move/edit with A/B still adjacent → same definition, `NEEDS_RECALC`).

The persisted pair A→B defines grading direction forever. LEFT/RIGHT are relative to stored A→B. If the Feature Line is reversed (current course stored B→A), the resolver reorients geometry back to A→B for grading (for arcs: reverse sweep/bulge logically, same precedent as `reverseFeatureLine` in `cadFeatureLineEdits.ts:264`). A reversal that changes no geometric/vertical content should not move the physical grading side and ideally leaves `grev1` unchanged (§7). GO gate + oracle.

## 3. Left / right convention

For persisted straight direction with unit tangent `T = (tx, ty)`: `Nleft = (-ty, tx)`, `Nright = (ty, -tx)`. Purely relative to persisted source direction. No drawing-North interpretation, no inside/outside inference. Mirror transforms reflect A/B coordinates, so mathematical left stays correct with no enum flip.

## 4. Fixed-grade and cut/fill criteria

Store ONE numeric authority: signed `gradeRatio = ΔZ / horizontal distance` (e.g. +0.02 rises outward, −0.02 falls, 0 level). Never persist competing percent/H:V/angle authorities; the UI accepts Percent or explicit H:V (e.g. `2H:1V` → magnitude 0.5) plus an explicit Up/Down/Level direction, normalizes to `gradeRatio`, and displays the resolved signed value. Unlabeled `2:1` is never silently assumed H:V.

Cut/fill mode persists normalized signed ratios with `cutGradeRatio > 0`, `fillGradeRatio < 0` (e.g. Cut `2H:1V` → +0.5, Fill `3H:1V` → −1/3). Classification derives from current geometry per interval: target above source → CUT (positive slope), target below → FILL (negative slope), target == source → tie distance 0. No persisted per-segment flag. Cut/fill therefore requires CURRENT target coverage of the source course: any source interval outside the target or in a target void BLOCKS calculation (classification cannot be guessed). Fixed-grade mode may still tie outward even when the source itself lies outside target coverage.

For straight courses, target−source Z along the source is piecewise linear: split spans exactly at target triangle crossings and at zero crossings of the target−source delta (reuse `clipTrianglePair` / `clipHalf` from the 18I/18J infrastructure). No sampled classification. At a cut/fill zero transition the tie distance is exactly 0 with no blend strip; mesh regions meeting there record CUT/FILL/FIXED classification for display only.

## 5. Exact straight-source mathematics

For a straight source course of length L with start `P0`, unit tangent `T`, selected outward normal `N`, source elevations `Z0 → Z1` (`gs = (Z1−Z0)/L`), and fixed outward slope `g`, map every target XY `Q` into the source-relative local frame `u = dot(Q−P0, T)`, `d = dot(Q−P0, N)`. This frame conditions projected-coordinate jobs (E≈2,000,000, N≈7,000,000) the same way 18F's integer-truncated local origins do.

Grading surface in local coordinates is one plane: `Zg(u,d) = Z0 + gs·u + g·d`. Each target TIN triangle is also one plane; mapped into `(u,d)` it stays affine, so `Delta(u,d) = Ztarget(u,d) − Zg(u,d)` is AFFINE per triangle. The daylight locus per triangle is therefore exactly: empty, one point, one straight segment, or a coincident region. The general-plane closed form `d = (Ztarget(P(u)) − Zsource(u)) / (g − gradTarget·N)` (nonzero denominator) pins the engine at start/mid/end.

Candidate discovery uses the CURRENT TIN's existing grid/bbox acceleration (`candidateTriangles`, `buildSurfaceGrid`) over the swept strip `0 ≤ u ≤ L`, `0 ≤ d ≤ maxSearchDistance`. Candidates may over-cover; final geometry stays exact. The grading solver needs a TRUE empty candidate result where appropriate — audit `CadSurfaceGrid` query behavior and introduce a precise shared candidate API if the profile helper's fallback (returning all triangles on empty query) is unsuitable; do not change profile behavior casually. Sort candidates deterministically (precedent: `findOverlappingPairs`, `candidateTriangles` both sort) so shuffled triangle order yields identical geometry, mesh, diagnostics, and digests.

Per clipped target polygon (clip to the strip rectangle with the existing scalar/polygon clippers), evaluate Delta at vertices and extract the zero set analytically (reuse/contour-plane, scalar-clip, and volume-plane helpers — generalize, do not invent a fourth inconsistent subsystem). Collect exact zero segments in `(u,d)` space and build the nearest-positive lower envelope: for fixed station `u`, the selected daylight distance is the minimum `d ≥ 0` among valid roots (`NEAREST OUTWARD` is the only 20B policy; record `multipleSolutionCount`).

Continuity is fail-closed: full source-interval coverage is required. If the nearest branch disappears, reappears, or jumps to a disconnected farther branch → `GRADING_BRANCH_DISCONTINUITY` / `GRADING_NO_SOLUTION`, never a bridge line through empty space. Target void under any required interval → `TARGET_GAP` fail (no interpolation across voids, no reaching across a hole unless a continuous grading ray genuinely intersects valid target there under the envelope rules). Tie exactly on the retained boundary is valid; beyond it there is no target (no hull extension). Parallel planes with no crossing → no solution (no denominator fudge, no huge-distance artifact). A nonzero-area coincident patch → `GRADING_COINCIDENT_TARGET` (infinitely many ties; no arbitrary interior daylight) unless the only solution is the zero-width already-tied source boundary.

Every definition requires `maxSearchDistance > 0` (engineering search limit, not a tolerance): `0 ≤ d ≤ maxSearchDistance`, tie exactly at max allowed, true tie beyond max → `MAX_DISTANCE_REACHED`. One-course grading normally derives one continuous daylight path; represent segmentation internally only for zero-width transitions/diagnostics — CURRENT requires complete coverage with no hidden gap.

## 6. Numerical policy and Z authority

Machine-conditioning only: reuse `zeroDelta` (`4·ε·max(1,|·|)`) for scalar zero classification, duplicate-intersection cleanup, and plane agreement. No survey tolerance (5 mm etc.) as a daylight correctness threshold. At every tie point, target-plane Z and grading-plane Z must agree within the numeric floor; the result persists ONE deterministic value (preferred: grading-plane Z after proven agreement, never an average). Strong validation: query the CURRENT target mesh at every output daylight vertex and require agreement (GO gate). Source mesh vertices must equal the Feature Line evaluated at the same persisted station (exact for straight; on-arc + exact station-Z for curve samples — GO gate). Every straight exact mesh triangle is pinned by sampling deterministic interior points: cross-gradient in the grading normal direction matches `g` within conditioning (no warped triangles).

## 7. Revision, status, cache, worker

`grev1` (via shared `fnv1a`) covers: source Feature Line id, stored A/B vertex ids, resolved source XYZ/plan geometry in A→B direction, target Surface id + target's current source revision, side, criterion numeric ratios, `maxSearchDistance`, curve tolerance. Excludes name/layer/colors/opacity/display toggles — appearance never recalculates geometry.

Status is derived-only (`BUILDING`, `BROKEN_REFERENCE`, `SOURCE_NOT_CURRENT`, `UNBUILT`, `FAILED`, `NEEDS_RECALC`, `CURRENT`, plus result diagnostics `NO_SOLUTION`, `TARGET_GAP`, `MAX_DISTANCE_REACHED`, `COINCIDENT_TARGET`, `BRANCH_DISCONTINUITY`). Target edit → target `NEEDS_REBUILD` → grading `SOURCE_NOT_CURRENT`; target rebuild → `NEEDS_RECALC`; source geometry change → new `grev` → `NEEDS_RECALC`; course unresolvable → `BROKEN_REFERENCE`. Never persist status; reopen is `UNBUILT`, never false-CURRENT. Session cache keys on `drawingId + gradingId + grev`, retaining at most current + one stale (stale renders only as out-of-date, never CURRENT), mirroring Surface/Profile/Analysis conventions.

Grade-to-Surface runs off-main-thread by extending the shared Surface worker: flat snapshots only (grading id, revision, source course geometry, target current TIN + grid/index data, criterion, side, max distance, curve tolerance — no `CadProject`, no React, no project mutation in worker). Response carries daylight geometry, grading TIN, statistics, diagnostics, revision/request identity. Latest-wins: `drawingId + gradingId + revision + requestId`; on completion re-read definition/sources and DISCARD if the revision moved (no transaction); newer Calculate wins; drawing switch/unmount cleans up safely. Calculate is explicit (creation/edit never auto-launches heavy work); stale-worker oracle: late results never become CURRENT.

## 8. Mesh, curve approximation, result model

Each daylight interval `[u0,u1]` with source points and daylight points forms one strip cell; within one straight span under one cross-slope the four corners are coplanar — triangulate deterministically (no Delaunay, no raster). The derived TIN must pass the NORMAL explicit-TIN validator (finite XYZ, CCW nonzero faces, no duplicate faces, edge-manifold, no illegal XY crossings, no conflicting duplicate XY, no T-junctions) — reuse `validateExplicitTinPayload`, emitting CCW faces to pass it. Zero-width ties (`d = 0`: isolated transitions, endpoints, whole-interval) emit no tiny strips and skip zero-area triangles; a fully already-tied course is `CURRENT` with `ALREADY_TIED`, zero area, and Bake disabled.

Curved sources are explicitly APPROXIMATED, never exact: linearize the arc by persisted `curveChordTolerance` (authoritative approximation input, not display tessellation; reuse `featureLineArcSubdivisions` sagitta policy + `resolveSurfaceBreaklineChordTolerance` resolution pattern, no hard-coded angular steps). Every sample lies on the exact arc with Z from exact arc-station interpolation; each chord grades through the exact straight solver. Result carries `EXACT` vs `CURVE_APPROXIMATED`. Convergence oracle: coarse/medium/fine tolerances must show sagitta within tolerance, monotone subdivision, and daylight/result convergence against a dense independent reference.

Result model (session-only, never persisted): grading id, revision, accuracy, regions, daylight segments, grading mesh (points/triangles), source length, plan/3D area, min/max/mean tie distance, cut/fill/tied source lengths, candidate-triangle and intersection-segment counts, diagnostics. Cut/fill mesh regions record CUT/FILL/FIXED for display only (never via Volume's earthwork zero policy).

## 9. Display, style, manager, commands, inquiry

Daylight display must be visually distinct from the source line; stale/failed states must be obvious; curve-approximated state must be visible. Style: prefer a small drawing-owned `CadGradingStyle` only if low-risk given existing style architecture (name, fixed/cut/fill/daylight colors, opacity, showTriangles/showDaylight — appearance-only, no revision impact, no legal meaning in colors); otherwise grading layer color + bounded display fields. Audit decides during implementation.

Manager lives at Toolspace Design → Gradings (Name, Source, Course, Side, Target, Criterion, Status, Max Distance, Accuracy; CURRENT rows add min/max tie, area, triangles; actions New/Calculate/Edit Criteria/Change Target/Extract Daylight/Bake Surface/Delete — no thousands of daylight children). Creation command `GRADETOSURFACE` (alias `GTS` if collision-free): select Feature Line → pick course → Left/Right/Both (Both atomically creates `<Name> - Left` + `<Name> - Right`) → select CURRENT target → Fixed vs Cut/Fill → slope inputs with resolved signed ratios shown → max distance → optional curve tolerance → Preview/Create → explicit Calculate. Side preview shows a short ghost arrow on the chosen side before commit (no mutation). Command set: `GRADETOSURFACE`, `GRADING`, `GRADINGCALC`, `GRADINGINQUIRY`, `GRADINGEXTRACTDAYLIGHT`, `GRADINGBAKE` (+ optional `GTS`), one shared registry, collision-checked. Properties shows definition + criterion + status + CURRENT metrics, no arrays. Ribbon: DESIGN/GRADING group or extend the Feature Line area (no tab explosion). Inquiry reports source/target/criterion/accuracy/lengths/tie min-max-mean/areas/cut-fill-tied lengths/daylight vertices/triangles/multiple-root events/diagnostics, no raw arrays. Grading CSV: Station, Source E/N/Z, Side, Classification, Tie Distance, Daylight E/N/Z (+ diagnostic triangle only if useful); no internal UUIDs as primary columns.

## 10. Extract, bake, downstream

`GRADINGEXTRACTDAYLIGHT` requires CURRENT: creates a NEW snapshot `CadFeatureLineEntity` (`<Grading Name> - Daylight`, fresh ids, exact cached tie XYZ, no live dependency, straight courses even for curve-approximated results — never infer arcs), one undo transaction. Moving the extract never affects grading; source/target/grading byte-identical.

`GRADINGBAKE` requires CURRENT + nonzero area + expected revision: creates a new `CadSurface` with `sourceKind: 'explicit-tin'` from the exact calculated mesh (canonicalized identically), mutating nothing else, one undo transaction, redo restores the snapshot without recomputation. Provenance extends the explicit-TIN truth table (`kind: 'webnet-grading-bake'` + grading id/name/revision, source FL id + A/B vertex ids, target id, accuracy — informational snapshot, never labeled LandXML/compose/generic bake). Post-bake independence is total (source/target/grading edits never touch the baked surface); the baked surface edits normally under 18S/18T/18V and composes under 18Y/18Z, but is NEVER auto-composed into the target (the source-side edge may intentionally not tie). Volume integration is Bake-then-normal-`CadVolumeSurface` through the untouched 18I engine (manager may offer an explicit shortcut that names the Bake step; no hidden conversion). The §70 triangular prism (100 m × 20 m × 10 m) must reproduce exactly 10,000 cubic units through ordinary 18I with 18I sign conventions. No grading branch in 18I or 18U.

## 11. Persistence, transforms, exports

WNCAD persists definitions (+ styles if introduced) only — never results, meshes, counters, indexes, or status. Undo/redo: definition CRUD, criteria edits, and target reassignment are history; Calculate and worker results are not; Extract and Bake are one entry each (undo Bake removes only the baked surface). Delete grading never cascades to extracts or baked surfaces (snapshots; warn only if UX needs provenance disclosure). Save/reopen keeps definitions byte-exact with honest `UNBUILT` status; recalculation reproduces geometry.

Project Transform (horizontal similarity, Z unchanged) and Grid/Ground (XY scale, Z unchanged) need a proven — not guessed — policy: distance-like quantities (`maxSearchDistance`, `curveChordTolerance`) scale by |k|; the outward `gradeRatio` criterion stays numerically fixed as design intent while source longitudinal grades change with XY scale; translation/rotation change nothing; results are never transformed — recalculation is required. Reviewer must approve the derivation. General MOVE/ROTATE of the source keeps refs and criterion with `NEEDS_RECALC` and no result transform; MIRROR keeps the side enum (mathematical left of the mirrored A→B is automatically correct).

Exports: SVG/PDF render CURRENT grading fill + daylight FULL (stale/non-current never exported as current — warn); DXF R12/R2000 represent daylight as 3D POLYLINE and mesh as 3DFACE where the serializers support it (audit first; curve-approximation warning rides along; no persisted semantics implied); LandXML does NOT gain a grading schema — `NOT_APPLICABLE`, workflow is Bake → normal Surface export, and omitting live grading geometry from direct export warns explicitly. The export matrix must separate semantic definition vs derived display vs snapshot output across SVG / PDF / DXF R12 / DXF R2000 / LandXML / WNCAD.

## 12. Performance and determinism

Benchmark real TINs at 1k/10k/50k/100k across flat, sloping, plane-break, rolling/multiple-root, void, cut/fill-transition, and curved coarse/fine cases; measure index prep, candidates, local transform, clipping, zero-segment extraction, envelope build, mesh construction, validation, total, heap-ish memory, and result sizes. Actually run 100k — no extrapolation as primary evidence. Complexity must be index cost + candidate interactions + result size, never `O(samples × all triangles)`; a 100k TIN with one ordinary course must be practical (no arbitrary timing gate). Determinism: shuffled triangles and shuffled grid-bucket insertion give identical results (sort before geometry ops, no worker scheduling nondeterminism). Large coordinates (E≈2M, N≈7M) must match translated-local equivalents within the numeric contract via the `(u,d)` frame.
